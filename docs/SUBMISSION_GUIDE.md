# Track A submission and demo guide

**Event:** Hacktoberfest Hack Day Gorakhpur × DDUGU, Saturday 10 October 2026, 11:00 AM–4:00 PM IST.

## Prepare your team project

1. Create a **new, public GitHub repository for your team**. Do not submit a pull request to the shared starter kit as your Track A project.
2. Push your modified notebook or project code. Provide run steps that work for a judge.
3. Include a clearly identified **open-source license** (MIT is an option if appropriate for your code); comply with licenses of any dependencies, models and data.
4. Fill in a [team README](../templates/TEAM_README_TEMPLATE.md): team, problem, AI component, original work, how to run, results, known limitations.
5. Validate the submitted URL in an incognito window to confirm judges can access it without permissions or API secrets.
6. Use the **official event project-submission process** described by organizers in the MLH event platform. One team representative should submit, ensuring all participants meet event registration and check-in requirements.

Official event link: https://events.mlh.com/events/15114-hacktoberfest-hack-day-gorakhpur-x-ddugu

**Do not assume** that a Google Colab link, GitHub issue, or GitHub pull request alone constitutes an official event submission. Confirm the published official challenge, deadline, team membership and eligible prize category with organizers.

## Local suggested timing within 13:35–15:35 sprint

| IST | Activity |
| --- | --- |
| 13:35–13:50 | Form team, choose challenge, run baseline |
| 13:50–14:50 | Add and test original functionality |
| 14:50–15:10 | Push code, complete README, prepare 90-second demo |
| 15:10 | Suggested local submission checkpoint (organizer to confirm and announce) |
| 15:10–15:35 | Table demos, feedback, official judging workflow as applicable |
| 15:35–15:50 | Finalists' stage demos, awards and recognition |

**Important:** The above is an organizer planning schedule, not a verified MLH system deadline. Official platform deadlines take precedence. Judges should begin viewing projects early if the team count is high.

## Demo structure: 90 seconds

- 15 s: the problem and users
- 35 s: running demonstration
- 20 s: open-source AI used and what's original
- 20 s: results, limitations, and your GitHub repository

Judges may ask follow-up questions. Prepare a screenshot or short screen recording in case Wi-Fi fails. Never stage a fake result.
